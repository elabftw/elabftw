# Contributing to eLabFTW

Please see the [documentation](https://doc.elabftw.net/docs/contributing/intro).

## Issue triage

In order to help organize issues, correct tags must be applied to new issues.

How to best label new issues:

- Is it a bug or a feature? Adjust tags if needed.
- Is it a duplicate? Close it using the "close as duplicate" feature of GitHub, pointing to the older issue.
- Is it reproducible? If it is reproducible, add the tag "reproducible", maybe a "priority:" tag, too. Otherwise, ask for more information and add the tags "not reproducible" and "more info required".
- What module is this related to? Add the corresponding "module:" tag if a pertinent tag exists.

Then answer:

- For bugs: write a brief message explaining whether it's reproducible or not.
- For feature requests, simply acknowledge the request with a generic message: "Thank you for your request, we will look into it".

## AI-assisted contributions

We welcome contributions that make use of AI tools. However, **AI assistance is not a substitute for human understanding, judgment, and responsibility**.

All contributions, regardless of how they were produced, must meet the following expectations:

- **Human review:** Contributors must thoroughly review, understand, and critically assess all AI-generated code before submitting it. You must be able to explain and justify your changes.
- **Quality over quantity:** Code should be clean, elegant, minimal, and consistent with the existing codebase. Avoid unnecessary abstractions, excessive complexity, duplication, and unrelated changes.
- **Testing:** Changes must be properly tested and verified by the contributor. AI-generated claims of correctness or successful tests are not sufficient.
- **Human responsibility:** Contributors remain fully responsible for the correctness, security, maintainability, and overall quality of their submissions.

**Fully autonomous, unreviewed AI-generated pull requests are not accepted.** We reserve the right to close contributions that do not meet these standards without conducting an extensive code review.

Our goal is to improve the project, not to increase the volume of contributed code.
